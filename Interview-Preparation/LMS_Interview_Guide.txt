- Single-digit millisecond latency
- Pay-per-request scaling
- Eventual consistency acceptable

- PK: tenantCode (multi-tenant)

- Rate limiting (Resilience4j)
- Pagination in chunks (1000 items)

# PART 3: AWS INTERVIEW GUIDE

## EventBridge

### Q1: What & Why
- Serverless event bus for routing
- Decouples publishers from consumers
- Cross-account event support
- Built-in retry + filtering

### Q2: Event Pattern Matching
- source, detail-type, detail fields
- AND logic within level, OR across values
- Prevents unintended events

### Q3: Lambda vs ECS Runtime
- Lambda: Direct invocation, 5-10s cold start, pay-per-invocation
- ECS: Always-on, 0s cold start, fixed cost
- Choose based on traffic pattern + cost

## SQS

### Q4: Queue Setup
- Visibility timeout: 300s
- Message retention: 4 days
- Long polling: 20s
- DLQ with maxReceiveCount: 3

### Q5: Message Flow
- EventBridge → SQS (ECS runtime)
- Message becomes invisible during processing
- On crash: Reappears after visibility timeout
- After 3 failures: Move to DLQ

### Q6: Dead-Letter Queue
- Isolated problematic messages
- 14-day retention for investigation
- Prevents infinite retries

## S3

### Q7: Event Notifications
- s3:ObjectCreated:* triggers Lambda
- Filter prefix/suffix for targeting
- Lambda processes media

### Q8: Presigned URLs
- Temporary access to private S3 objects
- Signed with AWS credentials
- Tenant isolation: S3 key includes tenant prefix
- Signature includes key path (unforgeable)

## API Gateway

### Q9: Lambda Authorizer Flow
1. Extract Origin header → resolve tenant
2. Load tenant-config.json from S3 (5-min cache)
3. Get Cognito pool for tenant
4. Verify JWT signature
5. Return Allow/Deny policy

### Q10: Verifier Caching
- Without: 550ms per request (fetch JWKS + verify)
- With: 51ms (1ms cache + 50ms verify)
- 10x throughput improvement

## Lambda

### Q11: Provisioned Concurrency
- Reserved warm instances
- Cost: .015/hour per unit
- Benefit: No cold starts
- Breakeven: High utilization (&gt;70%)

### Q12: Scaling Strategy (10x Traffic)
1. Lambda: Increase provisioned concurrency
2. DynamoDB: On-demand billing (auto-scale)
3. EventBridge: Already scales
4. Add caching (Redis)
5. Database optimization (GSI, denormalization)

## Multi-Region & Failover

### Q13: Failover Architecture
- Primary: ap-south-1
- Failover: us-east-1
- Route53: Health checks + weighted routing
- DynamoDB: Multi-region replicas
- EventBridge: Separate buses in each region

### Q14: Failure Scenario
- Health check fails (30s detection)
- Route53 failover activates (~1min total)
- Traffic routes to failover region

## Terraform

### Q15: Why Infrastructure as Code
- Repeatable (dev = prod = test)
- Version controlled

1. Request from https://tenant-a.lms.com
2. Lambda Authorizer extracts hostname
3. Looks up tenant-a in tenant-config (S3 cached)
4. Gets tenant-a Cognito pool ID
5. Verifies JWT with tenant-a keys
6. Backend sets TenantUtil = tenant-a
7. All DAOs filter by pk = tenant-a
8. Request from tenant-b cannot see tenant-a data

# COMMON INTERVIEW QUESTIONS & ANSWERS

### Q: How would you design a caching layer for this system?
A: 
1. In-memory: Caffeine for reference data (30-min TTL)
2. Distributed: Redis for user sessions + hot data
3. Edge: CloudFront for static assets
4. Invalidation: Publish events on data changes

### Q: How do you handle failures in EventBridge?
A:
1. Retry with exponential backoff (24 hours default)
2. DLQ captures final failures
3. Manual investigation + replay
4. Application-level idempotency for duplicates

### Q: What happens if Cognito is down?
A:
1. JWT verification fails
2. Lambda Authorizer returns Deny
3. Request rejected (403)
4. Circuit breaker prevents cascading retries

### Q: How do you scale to 10x traffic?
A:
1. Lambda: Provisioned concurrency
2. DynamoDB: On-demand or increase WCU
3. EventBridge: Already scales
4. Caching: Add Redis
5. Database: Add GSI, denormalize

### Q: How do you ensure data consistency in multi-region?
A:
1. Strong consistency in primary region
2. Eventual consistency in replicas
3. RPO (recovery point) ~seconds
4. Accept data loss if region fails
